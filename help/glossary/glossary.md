# Saiba mais sobre os termos e conceitos usados no Designer.

## #&#x200B;

|  |  |
| --- | --- |
| <b><span id="three-d-scene"></span>Cena 3D</b> | Uma coleção de objetos e dados envolvidos na representação e animação de uma visualização de espaço 3D:<ul data-preserve-html="true"> <li data-preserve-html="true">[Malhas](#mesh)</li> <li data-preserve-html="true">[Materiais](#material)</li> <li data-preserve-html="true">Câmeras</li> <li data-preserve-html="true">Luzes</li> <li data-preserve-html="true">Animação</li> <li data-preserve-html="true">Simulações</li> <li data-preserve-html="true">...</li> </ul>Os [formatos de arquivo populares](https://www.adobe.com/br/products/substance3d/discover/3d-files-formats.html) para armazenar cenas 3D incluem o [USD](#usd) da Pixar e o FBX da Autodesk. Nem todos os formatos de arquivo são compatíveis com todos esses componentes |

## A

|  |  |
| --- | --- |
| <b><span id="alpha"></span>canal de Alpha</b> | O quarto canal de uma imagem colorida, geralmente usado para descrever a opacidade. |
| <b><span id="ambient-occlusion"></span>oclusão de ambiente</b> | A atenuação da luz ambiente em superfícies menos expostas e, portanto, mais difíceis de alcançar. |
| <b><span id="anisotropy"></span>Anisotropia</b> | A propriedade de ser dependente da direção. Em outras palavras, fornecer um resultado diferente quando medido ou observado em um eixo diferente.   Os materiais anisotrópicos têm uma aparência diferente dependendo de onde são observados, e os filtros anisotrópicos não são aplicados uniformemente em todas as direções. |
| <b><span id="api"></span>API</b> | Uma Interface de Programação de Aplicativo (API) é um conjunto de funções e procedimentos que permite aos usuários acessar as funções e procedimentos de outro aplicativo do programa.   Uma API fornece uma camada controlada e segura entre o usuário e um programa. Ele também pode usar outra linguagem de programação para tornar esse programa mais fácil de interagir e mais amplamente acessível.   O Designer oferece uma [API Python](../scripting/scripting.md) que fornece acesso fácil a uma ampla variedade de recursos para manipular dados, criar ferramentas personalizadas e acelerar fluxos de trabalho. |
| <b><span id="atomic-node"></span>Nó atômico</b> | Os blocos de construção fundamentais do gráfico. Todos os [nós de instância](#instance-node) podem ser divididos em gráficos de nós atômicos. Cada tipo de grafo tem seu próprio conjunto de nós atômicos. |

## B

|  |  |
| --- | --- |
| <b><span id="baking"></span>Preparação</b> | O processo de calcular informações de um modelo 3D e armazenar os resultados em uma [textura](#texture). Os dados são colocados na textura de acordo com os [UVs](#uv) do modelo. |
| <b><span id="base-color"></span>Cor base</b> (Albedo) | Um canal de um [material](#material) definido usando o modelo de aspereza metálica PBR [sombreamento](#shader). A cor base especifica a cor de uma superfície sem informações de iluminação.   Não deve ser confundido com [Difuso](#diffuse). |
| <b><span id="base-parameter"></span>Parâmetro base</b> | Um parâmetro comum a todos os nós em um gráfico de Substance que calcula um [bitmap](#bitmap).   Estes incluem aspectos principais do bitmap, como sua resolução ([Tamanho de saída](#output-size)) e [profundidade de bits](#bit-depth) (Formato de saída), ou como o bitmap é calculado, como o modo [lado a lado](#tiling).   Os parâmetros base geralmente são [herdados](#inheritance) de outros nós upstream ou do gráfico que hospeda o nó. |
| <b><span id="bilinear-filtering"></span>Filtragem bilinear</b> | Um processo de interpolação usado em imagens por computador quando uma [amostra de textura](#texture-sampling) não é executada exatamente no centro de um pixel.   Por exemplo, isso pode ocorrer quando uma imagem é aumentada. |
| <b><span id="bit-depth"></span>Profundidade de bits</b> | O número de bits usados para armazenar o valor de um pixel em uma textura. Profundidades de bits mais altas permitem a codificação de mais valores, resultando em gradientes mais suaves.   Profundidades de bits diferentes estão disponíveis dependendo do tipo do valor: - Os valores inteiros podem ser codificados usando 8 bits (0 a 255) ou 16 bits (0 a 65.535). - Os valores de ponto flutuante podem ser codificados usando-se 16 bits (+32767.9999 a -32768.0 ) ou 32 bits (-3.4E+38 a +3.4E+38) As imagens de intervalo dinâmico baixo usam valores inteiros para codificar etapas de 0 a 1. As imagens de intervalo dinâmico usam valores de ponto flutuante para codificar valores numéricos brutos.   Nos gráficos de Substance, a profundidade de bits é controlada pelo parâmetro Formato de saída. |
| <b><span id="bitmap"></span>Bitmap</b> | Uma imagem digital. Dois tipos de imagens são mais comuns:<ul data-preserve-html="true"> <li data-preserve-html="true">As imagens em tons de cinza têm apenas um canal: luminância (L);</li> <li data-preserve-html="true">As imagens coloridas têm três canais: vermelho, verde e azul (RGB). Um quarto pode estar presente: alfa (A), que é frequentemente usado para opacidade. As imagens coloridas no Designer são sempre RGBA.</li> </ul>  Os bitmaps podem ser vistos como grades de valores. Cada célula dessa grade é um pixel, que é a abreviação de “elemento de imagem”. Um pixel armazena um valor por canal. O tipo desse valor depende da [profundidade de bits](#bit-depth) do bitmap. |

## C

|  |  |
| --- | --- |
| <b><span id="cache"></span>Cache</b> (Memória) | Uma coleção de dados - ex. [parâmetros base](#base-parameter) do nó e imagens de saída - armazenados na memória para serem reutilizados.   O cache acelera muito os cálculos do gráfico, permitindo que o [Substance Engine](#substance-engine) recalcule apenas as partes de um gráfico que foram alteradas. Ao ajustar as conexões e os parâmetros do nó, todos os nós que o precedem não são afetados por essas alterações, portanto, não precisam ser [avaliados](#evaluation) novamente para atualizar o gráfico. Seu cache é usado no lugar.   O cache pode ocupar uma parte significativa da memória ao trabalhar com altas resoluções e profundidades de bits em gráficos grandes. |
| <b><span id="channel-packing"></span>embalagem de canal</b> | Uma técnica de otimização em que imagens separadas são compactadas nos canais RGB(A) de uma imagem colorida única.   Por exemplo, uma textura RMA é um mapa de aspereza (R), um mapa de metalidade (M) e um mapa de oclusão ambiente (A), todos empacotados em uma textura de cor única.   Outra técnica comum é a embalagem de uma textura em tons de cinza no canal azul de um mapa normal, como o canal azul - ou seja, o componente &#39;Up&#39; do vetor normal - pode ser recalculado no tempo de execução.   O nó [mesclagem de RGBA](../compositing-graphs/nodes-reference-for-com/node-library/filters/channels/rgba-merge/rgba-merge.md) é útil para implementar essa técnica. |
| <b><span id="color-space"></span>Espaço de cores</b> | Uma definição de como um intervalo de cores é representado. A codificação e decodificação digital de uma cor específica requer essa definição para dar sentido aos números usados.   Um arquivo de imagem armazena valores de cores usando um espaço de cores especificado, para que essas cores possam ser reproduzidas fielmente em uma tela que ofereça suporte a esse espaço de cores. Um monitor tem recursos de reprodução de cores específicos que lhe permitem oferecer suporte total ou parcial a um determinado espaço de cores.   Dados brutos — por exemplo, um mapa normal - é sempre codificado e decodificado em um espaço de cores linear, pois essas cores não devem ser visualizadas e nenhuma transformação deve ser aplicada a esses dados.   O sRGB é um espaço de cores amplamente suportado. Outros espaços de cores populares incluem Adobe RGB, Rec. 2100 e ProPhoto RGB. |
| <b><span id="cooking"></span>Cozinhar </b>(<span id="compilation"></span>Compilação) | O processo de tradução de dados para outro idioma para que possam ser executados de forma rápida e eficiente. Computar o resultado de um gráfico de Substance exige compilá-lo primeiro. A compilação faz parte do processo de [avaliação](#evaluation) do gráfico.   Essa compilação é executada em um gráfico achatado, o que significa que todos os [nós de instância](#instance-node) são &#39;substituídos&#39; por seus gráficos de origem de modo que um gráfico maior permaneça, e esse gráfico seja o que for compilado.   Um gráfico compilado não é editável. O parâmetro exposto permanecerá disponível se for [dinâmico](#dynamic-parameter), enquanto os parâmetros [estáticos](#static-parameter) estiverem bloqueados e ocultos. |
| <b><span id="culling"></span>Selecionando</b> | Uma técnica de otimização para renderização de cenas 3D que remove a geometria dos cálculos de uma renderização quando não está visível.   Isso pode incluir objetos ou polígonos fora do fruto da câmera (*eliminação de afluxo*), voltados para o lado oposto da câmera (*remoção de fundo*) ou completamente ocultos por outros objetos opacos (*eliminação de oclusão*). |

## D

|  |  |
| --- | --- |
| <b><span id="dependency"></span>Dependência</b> | Um arquivo A usado por outro arquivo B de modo que o arquivo B não funcione conforme o esperado quando o arquivo A estiver ausente.   Uma dependência de um [pacote](#package) pode ser outro pacote porque faz referência a um gráfico dentro dele, um arquivo de imagem, uma fonte, etc. Um pacote armazena o caminho para sua dependência, e um aviso será emitido se a dependência não for encontrada nesse caminho. Dependências ausentes também podem resultar em [nós de instância fantasma](#ghost-instance-node) em um gráfico. |
| <b><span id="diffuse"></span>Difusa</b> | Um canal de um [material](../glossary/glossary.md) definido usando o modelo de Textura reluzente do Specular PBR [sombreamento](#shader). Difusa especifica a cor de uma superfície quando iluminada.   Não deve ser confundido com [Cor base (Albedo)](#base-color). |
| <b><span id="directx"></span>DirectX</b> | Uma coleção de APIs para manipulação de conteúdo multimídia. Sua API 3D, Direct3D, é amplamente utilizado no desenvolvimento de jogos eletrônicos e outras indústrias 3D.   O Direct3D posiciona a origem de uma textura, isto é, sua coordenada (0, 0), no *canto superior esquerdo*, (Y para baixo) enquanto a API do [OpenGL](#opengl) a coloca no *canto inferior esquerdo* (Y para cima).   Isso significa que um mapa normal de DirectX tem um *canal verde invertido* em comparação com o OpenGL. De fato, o canal verde hospeda a coordenada Y dos vetores normais. |
| <b><span id="displacement"></span>Deslocamento</b> | O processo de mover os [vértices](#vertex) de um modelo 3D, geralmente ao longo do [normal](#normal).   O deslocamento é frequentemente usado em combinação com [mosaico](#tessellation) e [mapas normais](#normal-map) para modelar detalhes mais finos em uma superfície. |
| <b><span id="dynamic-parameter"></span>Parâmetro dinâmico</b> | Um parâmetro cujo valor pode ser alterado. Em outras palavras, qualquer parâmetro cujo valor não seja constante é dinâmico.    Isso inclui parâmetros expostos, quaisquer parâmetros afetados por um parâmetro exposto e qualquer valor de parâmetro que seja afetado pela [amostragem em uma textura](#texture-sampling).   Ao contrário dos [parâmetros estáticos](#static-parameter), o valor dos parâmetros dinâmicos pode ser ajustado instantaneamente após o gráfico ser compilado em um arquivo SBSAR. |

## E

|  |  |
| --- | --- |
| <b><span id="evaluation"></span>Avaliação</b> | O processo de resolver a propagação de dados e parâmetros no gráfico. A avaliação verifica a validade de um gráfico e suas conexões, aplica [herança](#inheritance) e [cozinha](#cooking) o gráfico.   Na Exibição de gráfico, uma conexão é representada com uma linha pontilhada quando não é avaliada. A avaliação transforma a conexão em linhas sólidas.    Sempre que um parâmetro é ajustado em um gráfico, o nó que hospeda esse parâmetro e todos os nós downstream são [invalidados](#invalidation) e precisam ser reavaliados antes de serem [renderizados](#rendering). |

## F

|  |  |
| --- | --- |
| <b><span id="filter"></span>Filtro</b> (Nó) | Um nó que aplica uma modificação a uma imagem (por exemplo, uma deformação) ou extrai informações dela (por exemplo, uma máscara). |

## G

|  |  |
| --- | --- |
| <b><span id="ghost-instance-node"></span>Nó de instância fantasma</b> | Um [nó de instância](#instance-node) que faz referência a um subgrafo que não pode ser encontrado - isto é, uma [dependência](#dependency) ausente - está carregado como um nó de instância fantasma.   Os nós de instância fantasma são restaurados para o estado esperado resolvendo a dependência ausente e recarregando o [pacote](#package). |
| <b><span id="glossiness"></span>Textura reluzente</b> | Um canal de um [material](../glossary/glossary.md) definido usando o modelo de Textura reluzente do Specular PBR [sombreamento](../glossary/glossary.md). A textura reluzente especifica a rugosidade de uma superfície, isto é, variações microscópicas de height, também chamadas de *microfacetas*.   A alta luminosidade resulta em uma aparência suave, enquanto a baixa luminosidade resulta em uma aparência áspera e fosca.   É o inverso da [Aspereza](#roughness). |

## H

|  |  |
| --- | --- |
| <b><span id="histogram"></span>Histograma (imagem)</b> | No contexto de uma imagem, um histograma representa a população de valores em um determinado intervalo, geralmente [0, 1].   Essa população é visualizada usando barras verticais, onde um valor mais presente na imagem resulta em uma barra mais alta para esse valor. As barras são distribuídas horizontalmente de valores baixos (escuros) a valores altos (brilhantes).   Histogramas de imagens coloridas geralmente se sobrepõem aos histogramas de cada um de seus canais - normalmente R, G, B. |

## I

|  |  |
| --- | --- |
| <b><span id="inheritance"></span>Herança</b> | No contexto dos gráficos de Substance, a herança descreve a propriedade dos nós que adquirem valores de parâmetro de seus nós upstream ou seu gráfico pai.   Os parâmetros herdados incluem [resolução](#resolution) ([tamanho de saída](#output-size)), [profundidade de bits](#bit-depth) ([formato de saída](#output-format)) e [divisão em blocos gráficos](#tiling).   Saiba mais sobre herança nesta [página dedicada](../compositing-graphs/inheritance-compositing/inheritance-in-substance-compositing-graphs.md). |
| <b><span id="instance-node"></span>Nó de instância</b> | Um nó de instância representa um gráfico A em outro gráfico B. Nesse caso, o gráfico A pode ser chamado de [subgrafo](#subgraph) do gráfico B. Qualquer alteração no gráfico A é propagada para todos os nós de instância que a representam.   O nó de instância aplica seu próprio conjunto de valores para os parâmetros de entrada do gráfico A no contexto do gráfico B. Nesse sentido, o gráfico B pode hospedar vários nós de instância que todos os gráficos de referência A, mas cada um passa valores ou texturas diferentes como entradas no gráfico A.   Todos os nós na Biblioteca do Designer que não são [nós atômicos](#atomic-node) são nós de instância. |
| <b><span id="invalidation"></span>Invalidação</b> | O processo que declara que o resultado de um nó está desatualizado.   Quando um parâmetro é ajustado, o nó que hospeda esse parâmetro e todos os nós downstream são invalidados, portanto precisam ser [avaliados](#evaluation) e [renderizados](#rendering) novamente. |

## M

|  |  |
| --- | --- |
| <b><span id="material"></span>Material</b> | A coleção de propriedades e comportamentos da matéria no espaço, que inclui superfícies e volumes. A aparência de uma entidade no espaço 3D é definida por seu material.   Os materiais podem ser definidos de várias maneiras, e todas as definições não suportam todas as propriedades como refração, anisotropia ou brilho. Um [sombreador](#shader) é uma implementação específica de uma definição de material.   <b>Importante:</b> o termo &#39;material&#39; é um *termo abrangente* usado para se referir a várias coisas, incluindo:<ul data-preserve-html="true"> <li data-preserve-html="true">O [sombreador](#shader) usado para calcular a aparência de uma superfície ou volume;</li> <li data-preserve-html="true">O conjunto de [texturas](#texture) fornecido para um sombreador;</li> <li data-preserve-html="true">Uma ID de material, que é um atributo de uma primitiva 3D usada para distinguir as partes que usam materiais diferentes.</li> </ul> |
| <b><span id="mesh"></span>Malha</b> | Um objeto 3D composto de [vértices](#vertex) conectados por bordas para formar polígonos, como triângulos, que por sua vez são montados em superfícies. Estas superfícies podem ser abertas ou fechadas.   A aparência dessas superfícies é definida pelo [material](#material) atribuído a elas. O nível de detalhe de uma malha também é altamente dependente de seu [policount](#polycount). |
| <b><span id="metadata"></span>Metadados</b> | Dados que fornecem informações sobre o próprio arquivo, seu ambiente ou qualquer coisa relacionada aos dados do arquivo.   Os metadados comuns incluem o autor do arquivo, as datas de criação e modificação, os direitos autorais e a arte da capa.   No Designer, o conteúdo de um [pacote](#package) também pode ter metadados. Por exemplo, um gráfico de Substance que gera um material de estrutura pode ter metadados para as propriedades físicas da estrutura. |
| <b><span id="mipmap"></span>Mipmap</b> | Uma versão menor de uma textura, geralmente calculada automaticamente.   Uma textura pode ter uma pirâmide de versões menores de si mesma, que são intercambiáveis no tempo de execução para que o tamanho mais apropriado seja usado para obter a qualidade e o desempenho ideais.   Por exemplo, uma textura com detalhes de alta frequência exibidos em um tamanho menor provavelmente produzirá artefatos *moiré*. Além disso, uma textura maior provavelmente envolve mais [amostras de textura](#texture-sampling).   O termo &#39;mipmap&#39; origina-se da técnica de mapeamento MIP, onde MIP representa o latino &#39;*multum in parvo*&#39;, que significa &#39;muitas coisas em um lugar pequeno&#39;. |

## N

|  |  |
| --- | --- |
| <b><span id="node"></span>Nó</b> | Objeto em um gráfico que executa cálculos e gera um ou mais resultados.   O resultado é controlado usando parâmetros de entrada. Esses parâmetros podem ser listados como controles no Dock Propriedades ou como conectores de entrada no próprio nó.   Há duas categorias principais de nós: [nós atômicos](#atomic-node) e nós de instância. |
| <b><span id="noise"></span>Ruído</b> | Uma imagem não figurativa que representa uma distribuição aleatória ou pseudoaleatória de formas e cores. Ruídos são frequentemente usados para adicionar variação a superfícies ou deformações.   A biblioteca de nós do Designer inclui uma grande coleção de geradores de ruído, como [Manchas de P&amp;B](../compositing-graphs/nodes-reference-for-com/node-library/texture-generators/noises/bnw-spots-2/bnw-spots-2.md), [Nuvens](../compositing-graphs/nodes-reference-for-com/node-library/texture-generators/noises/clouds-2/clouds-2.md), [Ruído de perlin](../compositing-graphs/nodes-reference-for-com/node-library/texture-generators/noises/perlin-noise/perlin-noise.md) ou [Voronoi](../compositing-graphs/nodes-reference-for-com/node-library/texture-generators/noises/voronoi/voronoi.md). |
| <b><span id="normal"></span>Normal</b> | Na computação 3D, o normal de uma superfície é um vetor [normalizado](#normalization) perpendicular a essa superfície, saindo dessa superfície para fora.   Este vetor representa a orientação de uma superfície no espaço 3D e é usado para [sombreamento](#shader) que superfície de acordo com as luzes da cena e a perspectiva da câmera.   Uma textura de [mapa normal](#normal-map) pode ser aplicada a uma superfície para modificar seus normais e adicionar detalhes. |
| <b><span id="normal-map"></span>Mapa normal</b> | Uma textura aplicada em uma superfície para modificar seus normais.   É mais frequentemente usado para falsificar detalhes que seriam ineficientes para incluir na geometria de um modelo. O uso de tal mapa permite ter normais por texel além dos normais por vértice, resultando em mais informações sobre a superfície e, portanto, mais detalhes sobre a superfície.   As coordenadas X, Y e Z dos vetores normais são codificadas nos canais vermelho, verde e azul do mapa, respectivamente. Dependendo da API gráfica de destino ([DirectX](#directx) ou [OpenGL](#opengl)), o canal verde pode ser invertido. |
| <b><span id="normalization"></span>Normalização</b> | O processo de remapeamento de um intervalo de valores para o intervalo [0, 1], no qual o maior valor de entrada é remapeado para 1.0 e o menor valor de entrada é remapeado para 0.0.   Para vetores, a normalização é o ajuste do comprimento do vetor (ou &#39;magnitude&#39;) para um valor de 1,0. |

## O

|  |  |
| --- | --- |
| <b><span id="opengl"></span>OpenGL</b> | Uma API gráfica 3D amplamente usada no desenvolvimento de jogos eletrônicos e outras indústrias 3D.   O OpenGL posiciona a origem de uma textura, isto é, sua coordenada (0, 0), na *parte inferior esquerda*, (Y para cima) enquanto a API [DirectX](#directx) a posiciona na *parte superior esquerda* (Y para baixo).   Isso significa que um mapa normal OpenGL tem um *canal verde invertido* em comparação com o DirectX. De fato, o canal verde hospeda a coordenada Y dos vetores normais. |
| <b><span id="openusd"></span>OpenUSD</b> | Consulte [USD](#usd). |
| <b><span id="output-format"></span>Formato de saída</b> | [Parâmetro base](#base-parameter) dos nós em um gráfico de Substance que descreve a [profundidade de bits](#bit-depth) do nó. |
| <b><span id="output-size"></span>Tamanho da saída</b> | [Parâmetro base](#base-parameter) dos nós em um gráfico de Substance que descreve a [resolução](#resolution) do nó.   Saiba mais sobre o tamanho da Saída nesta [página dedicada](../compositing-graphs/output-size/output-size.md). |

## P

|  |  |
| --- | --- |
| <b><span id="package"></span>Pacote</b> | Um arquivo do Substance 3D ([SBS](#sbs-file)) é chamado de pacote, no sentido de que é um contêiner de recursos: gráficos, [bitmaps](#bitmap), [cenas 3D](#three-d-scene) etc. Um pacote também armazena caminhos para suas [dependências](#dependency), bem como [metadados](#metadata). |
| <b><span id="pattern"></span>Padrão</b> | Uma imagem que deve ser usada como modelo ou referência para produzir outra imagem.   Na maioria dos casos, um padrão é uma imagem destinada a ser repetida (por exemplo, lado a lado, dispersa aleatoriamente ou organizada de acordo com algum conjunto de regras). |
| <b><span id="pixel-ratio"></span>Taxa de pixels</b> | Este [parâmetro base](#base-parameter) controla a compensação da taxa de proporção da imagem no nível de pixel. Em outras palavras: se o tamanho do pixel deve ser compensado para conservar uma proporção quadrada em uma imagem não quadrada.   O parâmetro é usado por filtros não locais, ou seja, filtros que usam os valores de pixels adjacentes para calcular o valor de um pixel. |
| <b><span id="pixel-size"></span>Tamanho de pixel</b> | Esse parâmetro define o tamanho horizontal e vertical de um pixel.   Ele atua como multiplicador para filtros não locais, isto é, filtros que usam os valores de pixels adjacentes para calcular o valor de um pixel. |
| <b><span id="polycount"></span>Contagem de polígonos</b> | A quantidade de polígonos de uma [malha](#mesh) 3D. De fato, polycount é a abreviação de &#39;polygon count&#39;.   Mais polígonos podem modelar detalhes mais finos. Malhas com um baixo policontagem são chamadas de “baixo-poli”, enquanto policontadores mais altos são chamados de “alto-poli”. |
| <b><span id="primary-input"></span>Entrada primária</b> | O conector de entrada de um [nó de instância](#instance-node) do qual esse nó herda seus valores de [parâmetro base](#base-parameter).   A entrada primária é marcada com um pequeno ponto em seu conector e o sufixo &#39;(Primário) em seu rótulo.   Ao usar nós com mais de uma entrada, é *altamente* recomendado ter cuidado com quais de suas entradas são as principais e como elas afetam a [herança](#inheritance) em todo o gráfico. |
| <b><span id="procedural"></span>Procedimento</b> | A característica de um pedaço de dados ou artefato a ser criado seguindo um algoritmo de computador, em vez de manualmente.   O Designer usa um fluxo de trabalho de procedimento no qual o algoritmo é projetado como um gráfico de nó.     Fluxos de trabalho de procedimento permitem iterações mais rápidas porque variações e ajustes podem ser gerados rapidamente modificando o algoritmo e seus parâmetros.   Quando o resultado é inteiramente produzido pelo algoritmo, esse resultado é coloquialmente referido como sendo “100% processual”. A geração de procedimentos é às vezes reduzida para &#39;proc-gen&#39;.   A maioria dos geradores na biblioteca de nós do Designer é 100% processual, pois não exige nenhuma imagem de entrada para produzir um resultado. |
| <b><span id="publishing"></span>Publicação (SBSAR)</b> | No Designer, publicar se refere à exportação de um [pacote](#package) como um arquivo morto SBSAR que inclui versões [compiladas](#compilation) dos gráficos, seus recursos ([bitmaps](#bitmap), fontes etc.), suas predefinições, bem como seus [metadados](#metadata).   O arquivo SBSAR resultante pode então ser distribuído e usado em outros aplicativos da Substance 3D ou aplicativos de terceiros por meio de um [plug-in do Substance 3D](https://substance3d.adobe.com/plugins/). |

| <b><span id="rendering"></span>Renderizando </b>(Exibição 3D) | O processo de calcular uma imagem de acordo com os dados de entrada, usando um programa como o [renderizador](#renderer). |

Mais pixels permitem representar detalhes mais sutis.   Em gráficos de Substance, a resolução de um bitmap computado por um [nó](#node) é controlada pelo &#39;[tamanho da saída](#output-size)&#39; [parâmetro base](#base-parameter) do nó. |
| <b><span id="roughness"></span>Aspereza</b> | Um canal de um [material](../glossary/glossary.md) definido usando o modelo de aspereza metálica PBR [sombreamento](../glossary/glossary.md). A aspereza especifica a rugosidade de uma superfície, ou seja, variações microscópicas de height, também chamadas de *microfacetas*.   A alta aspereza resulta em uma aparência fosca, enquanto a baixa aspereza resulta em uma aparência suave e brilhante.   É o inverso da [Textura reluzente](#glossiness). |

## S

| <b><span id="sbs-file"></span>Arquivo SBS</b> | SBS significa &#39;Substance 3D file&#39;. Este arquivo é usado para armazenar projetos do Substance 3D Designer. Seus dados usam o formato [XML](#xml). Consulte [pacote](#package). |

Este arquivo é usado para armazenar gráficos Substance 3D Designer compilados e os recursos necessários ([bitmaps](#bitmap), fontes etc.).   SBSAR é o formato de arquivo principal usado para distribuir gráficos de Substance que estão prontos para serem consumidos por outros aplicativos da Substance 3D e plug-ins do Substance 3D.   Como os gráficos armazenados em arquivos SBSAR são compilados, eles não podem ser carregados e editados no Substance 3D Designer. No entanto, arquivos SBSAR podem ser abertos usando o [7Zip](https://www.7-zip.org/) para recuperar seus parâmetros, predefinições e metadados em um arquivo [XML](#xml) inserido. |
| <span id="sdf"></span><b>FDS</b> | Consulte [Campo de distância assinado](#signed-distance-field). |
| <b><span id="shader"></span>Sombreador</b> | Programa que calcula a aparência de uma superfície ou volume de acordo com suas propriedades de [material](#material), a luz que recebe e de onde está sendo visualizada. Um sombreador é uma implementação específica de uma definição de material.   Texturas podem ser fornecidas a um sombreador para orientar seu comportamento. Os valores brutos também podem ser usados. Na [exibição 3D](../interface/3d-view/3d-view.md), vá para o menu &#39;Materiais&#39; para ver qual sombreador está sendo usado por um material na cena atual. O menu também permite acessar as [propriedades do sombreador](../interface/3d-view/3d-view.md) e quais texturas e valores estão sendo usados atualmente pelo sombreador.   Às vezes, &#39;Shader&#39; é usado de forma intercambiável com &#39;[Material](#material)&#39;. |
| <span id="sheen"></span><b>Brilho</b> | O aspecto brilhante ou brilhante de um tecido.   Este termo é amplamente utilizado na indústria têxtil para descrever uma propriedade reflexiva que adiciona um brilho colorido sutil. |
| <b><span id="signed-distance-field"></span>Campo de distância assinado (SDF)</b> | <p>Um campo de distância com sinal é uma função matemática que define uma superfície no espaço 3D calculando a distância de qualquer ponto no espaço até o ponto mais próximo na superfície.</p><p>Saiba mais sobre o conceito e como ele é usado no Designer aqui: [Trabalhando com o Função SDF](../function-graphs/nodes-reference-for-fun/function-node-library/function-nodes-sdf-functions/working-with-sdf-functions.md#what-is-an-sdf-function).</p> |
| <b><span id="spline"></span>Spline</b> | Geralmente, uma curva modelada usando uma função matemática, que permite desenhar formas limpas e suaves em qualquer resolução. O Designer usa uma aproximação com perdas codificada em uma textura usando um formato de dados personalizado.   Os splines oferecem controles intuitivos de comprimento e trajetória, incluem outros dados como thickness e height e fornecem acesso fácil à distância e à direção em qualquer ponto ao longo deles.   Essas qualidades fazem deles uma ferramenta poderosa para desenho e texturização. |
| <b><span id="static-parameter"></span>Parâmetro estático</b> | Um parâmetro cujo valor não pode ser alterado.   Ao contrário dos [parâmetros dinâmicos](#dynamic-parameter), os parâmetros estáticos não podem ser alterados imediatamente quando o gráfico é compilado em um arquivo SBSAR. Eles podem ser expostos e modificados no Designer somente enquanto o gráfico está sendo criado.   O Modo de visualização ocultará esses parâmetros em alguns casos, pois visa corresponder o comportamento dos arquivos SBSAR publicados o mais próximo possível.   Uma lista de parâmetros estáticos está disponível [aqui](../compositing-graphs/manage-parameters/exposing-a-parameter/exposing-a-parameter.md). |
| <b><span id="subgraph"></span>Subgrafo</b> | Um gráfico usado em outro gráfico como um [nó de instância](#instance-node). |
| <b><span id="substance-engine"></span>Substance Engine</b> | Uma tecnologia proprietária desenvolvida pela equipe do Substance 3D, responsável pela computação de imagens executando uma grande quantidade de transformações, efeitos e composição de imagens de entrada, com muita eficiência.   O Substance Engine implementa e computa os [nós atômicos](#atomic-node) do Designer.   O mecanismo é implementado através de diferentes backends, de acordo com a plataforma em que é executado: CPU, GPU e sistema operacional. No Designer, é possível alternar as infraestruturas acessando [Ferramentas > Alternar mecanismo](../interface/the-main-toolbar/the-main-toolbar.md).   Alguns back-ends oferecem um desempenho significativamente melhor do que outros, por exemplo, o back-end da GPU é muito mais rápido do que a CPU, e os resultados podem ser ligeiramente diferentes entre os backends. |
| <b><span id="substance-graph"></span></b><b>gráfico de Substance</b> (ou gráfico de composição de Substance) | Um gráfico que gera um ou mais [bitmaps](#bitmap).   Um gráfico de Substance pode ser usado para vários propósitos: - Produzir um conjunto de bitmaps que são texturas que descrevem um material; - Executar processamento de imagem em uma ou mais entradas de bitmap, como um filtro; - Gerar ruídos, padrões ou dados brutos, como um gerador. |

## T

|  |  |
| --- | --- |
| <b><span id="tessellation"></span>Mosaico</b> | Em computação gráfica, mosaico é o processo de subdividir uma superfície em mais polígonos, geralmente triângulos.   Esse processo pode ser executado em tempo de execução para aumentar dinamicamente a quantidade de polígonos de um modelo 3D, geralmente em combinação com [deslocamentos](#displacement) e [mapas normais](#normal-map) para modelar detalhes mais finos usando os polígonos adicionados. |
| <b><span id="texel"></span>Texel</b> | A unidade de informação de uma [textura](#texture), da mesma forma que um pixel é a unidade de informação de uma imagem. |
| <b><span id="texture"></span>Textura</b> | Uma imagem usada para representar gráficos, descrever as propriedades de [material](#material) de uma superfície fornecendo valores a um [sombreador](#shader) e codificar dados brutos em seus [texels](#texel).   Texturas são objetos que podem ser descompactados e manipulados com muito eficiência por GPUs. Na maioria dos casos, essa eficiência requer texturas para usar o poder de duas resoluções. Por exemplo, 1024x1024, 4096x4096, 512x256 etc. |
| <b><span id="texture-sampling"></span>Amostragem de textura</b> | Adquirindo o valor de uma [textura](#texture) em um local específico.   Alguns algoritmos exigem que muitas amostras sejam executadas para comparar valores, calcular sua média ou outras operações.   Se uma amostra não for executada exatamente no centro de um pixel, há duas opções no Designer para o valor que deve ser adquirido:<ul data-preserve-html="true"> <li data-preserve-html="true"><b>Mais próximo:</b> o valor do pixel mais próximo de acordo com seu centro</li> <li data-preserve-html="true"><b>Filtragem bilinear:</b> o valor da interpolação entre os pixels vizinhos horizontal e verticalmente, onde os pixels mais próximos têm mais peso.</li> </ul> |
| <b><span id="tiling"></span>Divisão em blocos gráficos</b> | A repetição de uma imagem horizontal, vertical ou ambas, sem emendas visíveis ou descontinuidade visual.   O Designer oferece muitos [nós](#node) que geram [ruídos](#noise) ou [padrões](#pattern) que são ladrilhados. Da mesma forma, muitos nós do tipo [filtro](#filter) foram criados para processar imagens, preservando a divisão em blocos gráficos. |

## U

|  |  |
| --- | --- |
| <b><span id="usage"></span>Uso (saída)</b> | Em gráficos de Substance, um Uso é um atributo de um nó [Saída](../compositing-graphs/nodes-reference-for-com/atomic-nodes/output/output.md) usado para permitir que o aplicativo saiba como conectar uma [textura](#texture) ao [sombreador](#shader) na [exibição 3D](../interface/3d-view/3d-view.md).   Ao aplicar um gráfico de Substance à visualização 3D, todas as saídas são conectadas ao sombreador com base nos usos correspondentes. Ou seja, &#39;basecolor&#39; para &#39;basecolor&#39;, &#39;rugosidade&#39; para &#39;rugosidade&#39; e assim por diante.   Os usos também são usados para corresponder conectores ao usar os [modos de criação de link](../interface/the-graph-view/link-creation-modes/link-creation-modes.md) &#39;Material&#39; e &#39;Material Compacto&#39;. |
| <b><span id="udim"></span>UDIM</b> (blocos UV) | Um padrão para dividir o espaço [UV](#uv) em ladrilhos com um identificador numérico exclusivo, o que permite atribuir uma textura diferente a cada ladrilho.   Os fluxos de trabalho UDIM são comuns em pipelines VFX, onde ativos de alta fidelidade exigem tantos detalhes que várias texturas de alta resolução são necessárias. Nesse caso, os [UV](#uv)s do ativo são organizados em vários UDIM (ou blocos UV).   O Designer oferece suporte a fluxos de trabalho UDIM e pode atribuir um Substance gráfico diferente por UDIM. |
| <b><span id="usd"></span>USD</b> (ou OpenUSD) | O [Universal Scene Description](https://openusd.org/release/index.html) (USD) é um formato de descrição de cena 3D criado pela Pixar para interoperabilidade e troca de dados entre aplicativos e plataformas.   Arquivos USD incluem a definição de dados usados em uma cena, bem como a composição dessa cena e tudo o que ela envolve: modelos, materiais, câmeras, animações, simulações etc. Um arquivo USD pode incluir qualquer tipo de dados, desde que o aplicativo tenha acesso ao plug-in USD que permite ler e usar esses dados corretamente.   A Adobe está [envolvida na Alliance for OpenUSD](https://blog.adobe.com/en/publish/2023/08/01/powering-3d-interoperability-continued-collaboration-through-openusd), um consórcio de atores do setor 3D que contribuem ativamente para o desenvolvimento e a padronização do formato. |
| <b><span id="uv"></span>UV</b> | UVs são uma representação de um modelo 3D em um espaço 2D. Eles são usados para mapear imagens 2D do espaço 2D para a superfície do modelo no espaço 3D.   O processo de criação de UVs é geralmente descrito como fazer emendas no modelo para o desdobrar e nivelar. |
